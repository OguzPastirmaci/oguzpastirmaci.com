Inside dranet

Follow one network device from discovery on the host, through a ResourceClaim, into a Pod network namespace, and back to the host. Each step names the Go code that does the work.

Two callers

The kubelet calls dranet over the DRA gRPC API for slow preparation work. The container runtime calls it over NRI while it builds each Pod.

Beside CNI

CNI still owns eth0 and the Pod IP. dranet adds whole devices to the Pod: NICs, SR-IOV VFs, RDMA devices, or IPvlan children.

One handoff

The PodConfigStore carries every decision from Prepare to the NRI hooks. A bbolt file keeps it across driver restarts.

    Where the applied config comes from

    Prepare turns several inputs into one stored DeviceConfig. On a conflict, your config wins, then the provider config, then the profile. A later stage only fills fields that are not set and adds list entries.

    1. Pick one opaque config

      From status.allocation.devices.config, keep entries for driver dra.net that match the request. Kubernetes lists DeviceClass entries before claim entries. The first non-empty entry is used, and later entries are not read. An invalid entry before it fails the claim.

      dra_hooks.go:241

    2. Merge onto the provider config

      The provider config is the base. User values win for single fields. Lists are appended and de-duplicated with the user entry kept. Routes are keyed by destination and table.

      config_merge.go:30

    3. Resolve the profile

      If the result names a profile, the profile provider (cloud or webhook) returns more config. It fills fields that are still not set and adds list entries. Without a profile provider, the inventory drops a profile that the cloud provider advertised.

      dra_hooks.go:772

    4. Validate again

      Provider and profile output is external input. The merged result is defaulted and validated before use. A failure releases the profile, so a retry cannot leak it.

      dra_hooks.go:786

    5. Add the host snapshot

      Host addresses, routes, rules, permanent neighbors, and RDMA device files are added. Then the DeviceConfig is saved for the Pod and device.

      dra_hooks.go:381

    Restart and shutdown

    After a restart

    • The bbolt file reloads every stored device config. Netns paths are not stored. Synchronize gets them again from the runtime.
    • Prepare is idempotent. A device already stored for the Pod is reused, so a second profile allocation cannot leak.
    • NRI hooks must be idempotent too. The runtime can retry a Pod start many times, and each retry calls the hooks again.
    • A save goes to bbolt before memory. If the disk write fails, Prepare fails and memory does not change.

    pod_device_config.go:187 · nri_hooks.go:43

    Graceful stop

    1. Stop the kubelet plugin. No new Prepare calls arrive.
    2. Wait until each prepared Pod has had no NRI activity for 10 s. Poll every 5 s. Give up after 5 min. The Pod termination grace period (30 s by default) usually ends first.
    3. Cancel the context and stop the NRI plugin.

    This order stops a Pod from starting without its devices when dranet is upgraded while Pods are being created.

    driver.go:266
